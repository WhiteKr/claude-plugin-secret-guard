# secret-guard

코드, 도구 출력, 대화에 들어 있는 키와 토큰을 모델이 읽지 못하게 가리는 Claude Code 플러그인입니다.
모델은 실제 값 대신 `<<secret:LABEL:ID>>` 자리표시자를 봅니다.
모델이 이 자리표시자를 Edit, Write, Bash 같은 도구 입력에 쓰면, 도구가 실행되는 순간에만 실제 값으로 바뀝니다.
그래서 "이 토큰을 .env로 옮겨 줘", "이 키를 설정에 넣어 줘", "CI 시크릿으로 등록해 줘" 같은 일을 값을 보여 주지 않고 맡길 수 있습니다.

## 설치

터미널 세션의 입력창에서 다음을 입력합니다.

```
/plugin install secret-guard --marketplace WhiteKr/whitekr-claude-plugins
```

`Add marketplace?`에 `y`로 답하고 설치 범위를 고릅니다.

셸에서 설치하려면 다음을 실행합니다.

```bash
claude plugin install secret-guard --marketplace WhiteKr/whitekr-claude-plugins
```

## 기능

- 대화에 저장되는 모든 행을 검사해 비밀 값을 자리표시자로 바꿉니다. 도구 결과, 프롬프트, 첨부, `@` 멘션 파일, CLAUDE.md가 대상이고, 서브에이전트의 행도 포함합니다. 관리 설정이 있는 기계에서는 예외가 있습니다([관리 설정이 있는 기계](#관리-설정이-있는-기계) 참고).
- 값을 가린 행에는 자리표시자를 어떻게 쓰는지 알려 주는 한 줄 안내가 붙습니다. 사용자가 보낸 프롬프트에는 안내를 본문에 넣지 않고, 사용자에게 보이지 않는 문맥으로 따로 붙입니다. 그래서 턴을 되돌리거나 취소해 프롬프트가 입력창으로 돌아와도 안내가 섞여 들어오지 않습니다. 돌아온 프롬프트 속 값은 자리표시자로 남지만, 그대로 다시 보내도 도구에서는 실제 값으로 바뀝니다.
- 검사에 실패한 행은 원문 대신 `[secret-guard: 내용을 검사하지 못해 숨김]`으로 저장합니다.
- 도구가 실행되기 직전에 입력 속 자리표시자를 실제 값으로 바꿉니다. 도구 결과는 다시 가려진 채로 모델에게 돌아갑니다.
- 이 세션이 모르는 자리표시자가 든 도구 호출은 실행하지 않고 거부합니다. 그래서 파일에 `<<secret:…>>` 문자열이 그대로 써지는 일이 없습니다.
- 실제 값으로 바꿔 주는 도구는 로컬 파일을 읽고 쓰거나 로컬 명령을 실행하는 도구뿐입니다. Edit, Write, MultiEdit, NotebookEdit, Bash, Read, Grep, Glob이 여기에 해당합니다.
- 네트워크로 나가는 도구에 자리표시자가 들어가면 실행하지 않고 거부합니다. WebFetch, WebSearch, MCP 도구가 여기에 해당합니다. 악성 문서가 "이 토큰을 이 주소로 보내라"고 시켜도 값이 밖으로 나가지 않습니다. MCP 도구가 자리표시자 문자열을 그대로 CI 시크릿 같은 곳에 저장하는 일도 막습니다. 데스크톱 앱 자체의 MCP 도구(`mcp__ccd_*`)는 로컬 도구라 거부하지 않습니다.
- 그 밖의 도구에 넘긴 자리표시자는 바꾸지 않고 그대로 전합니다. Agent, SendMessage, AskUserQuestion, 할 일 목록(TaskCreate, TodoWrite), 계획 모드(ExitPlanMode)가 여기에 해당합니다.
- 모델에게 보내는 요청은 멈추지 않습니다. 이 플러그인을 거치지 않는 경로로 들어온 값은 원본 그대로 모델에게 갑니다. 아래 "관리 설정이 있는 기계"를 보세요.

## 화면 표시

모델은 자리표시자만 봅니다. 화면에는 실제 값이 그려집니다. 화면에 그리는 방식만 바꾸므로 모델이 읽는 내용은 그대로입니다.

- 데스크톱, VS Code, 모바일에서는 답변 속 값을 칩으로 그립니다. 칩은 평소에 흐릿한 가짜 글자와 눈 가림 아이콘을 보여 주고, 마우스를 올리면 실제 값과 눈 아이콘으로 바뀝니다. 평소 상태에서는 실제 값을 아예 그리지 않습니다.
- 터미널에서는 같은 색 막대로 값을 가리고, 마우스를 올리면 값이 보입니다.
- 답변 속 칩 안쪽, 값 바로 뒤에는 무채색 ⧉ 버튼이 있습니다. 누르면 실제 값이 클립보드에 복사되고, 알림에는 이름만 나옵니다. 모델은 아무것도 보지 못합니다.
- 도구 행(파일 쓰기, 명령 출력)은 앱이 그리는 영역이라 칩을 넣을 수 없습니다. 그래서 값 앞에 🙈를 붙여 보여 줍니다.
- 사용자 메시지는 앱의 말풍선을 그대로 두고, 직접 입력한 값 앞에 🙈를 붙여 보여 줍니다. 이 세션이 모르는 자리표시자를 붙여 넣었다면 적은 그대로 보입니다.
- 칩이 든 문단은 이 플러그인이 직접 그립니다. 그래서 그 문단의 굵은 글씨나 인라인 코드 같은 서식은 빠지고, 표 안의 값은 표 대신 줄 단위로 그려집니다.

## 찾는 값

- PEM 개인 키 블록
- GitHub, Anthropic, OpenAI, AWS, Slack, GitLab, Google, Stripe, npm, Hugging Face, SendGrid, DigitalOcean, Telegram 봇 토큰과 Google OAuth 클라이언트 시크릿(`GOCSPX-`)
- JWT, `Bearer` 토큰, `user:password`로 풀리는 `Basic` 인증 값. 사용자 이름이나 비밀번호 한쪽이 비어 있어도 가립니다.
- Discord와 Slack 웹훅 URL의 토큰 부분. 호스트와 ID는 그대로 보입니다.
- URL 속 비밀번호 (`postgres://user:비밀번호@host`)
- 이름에 secret, token, password, api_key, access_key, account_key, auth, credential 등이 들어간 대입문의 값 (.env, YAML, JSON, `export`, Azure 연결 문자열의 `AccountKey=`)

다음은 가리지 않습니다.

- 커밋이나 해시처럼 이름이 그 값의 정체를 밝히는 경우의 git SHA와 UUID
- `${VAR}`나 `process.env.X` 같은 변수 참조, `changeme` 같은 예시 값, 숫자뿐인 값
- 꺾쇠 없이 적은 자리표시자 (`url-password:afe8c904c2e6`, `secret:github-token:0123456789ab`)
- 코드 식별자, 타입, 호출처럼 보이는 값 (`token: string)`, `tokens[1]`, `"accounts.User"`, `"LlamaTokenizerFast"`)
- 따옴표 속 숫자 없는 단어나 문구 (`"Required"`, `'Publish token'`)
- 다음 줄의 내용. 이름과 값은 같은 줄에 있어야 합니다. 그래서 YAML의 `auth:` 아래 줄은 값으로 보지 않습니다.
- 파일 이름, 테스트 ID, grep 결과의 경로 부분, AWS ARN (`tests/test_auth.py::test_login`, `src/auth/token.ts:42:`). 그 뒤에 오는 대입문(`app.env:3:API_KEY=…`)은 가립니다.
- 사용자 이름이나 스킴과 같은 URL 비밀번호 (`postgres://postgres:postgres@localhost`, `amqp://guest:guest@`). 로컬 기본값이기 때문입니다.
- `sk-learn-…`처럼 숫자가 없는 하이픈 이름

한 번 본 값은 원문 그대로 나타나도, base64로 나타나도 같은 방식으로 가립니다. 다만 더 긴 단어의 일부일 때는 가리지 않습니다. `Pa55word1`을 가렸어도 `Pa55word123`은 그대로 둡니다. 숫자 없는 단어 같은 값(`helpdesk`)은 `.`이나 `-`로 이어진 도메인과 이름(`helpdesk.zio.run`, `zio-helpdesk-api`) 속에서도 가리지 않습니다.

## 명령

`/secret <값>`은 규칙에 걸리지 않는 값을 직접 등록합니다. 평범한 비밀번호가 그런 예입니다.
등록하면 자리표시자가 입력창에 들어가고, 이후 그 값이 나오는 곳은 모두 가려집니다. 값은 8자 이상이어야 합니다.

## 값이 머무는 곳

- 실제 값은 세션 메모리(`$.state`)에만 있고 디스크에 쓰지 않습니다.
- 자리표시자 ID는 HMAC-SHA256의 앞 12자리입니다. 키는 기기마다 하나씩 `$.store`에 둡니다. 그래서 같은 값은 세션이 바뀌어도 같은 ID를 받습니다.
- 새 세션에서는 원본 파일을 다시 읽어야 그 자리표시자를 다시 쓸 수 있습니다.

## 한계

- 오탐을 줄이려고 정한 규칙 때문에 놓치는 비밀번호가 있습니다. 숫자 없는 비밀번호(`DB_PASSWORD=Secretpass`, `"MySecretPass"`), 따옴표 없이 괄호가 든 비밀번호, 사용자 이름과 같은 URL 비밀번호가 그렇습니다. 이런 값은 `/secret`으로 등록하세요.
- 옵션에 붙여 쓴 비밀번호(`mysql -pS3cret`)와 한글 이름의 대입문(`비밀번호: …`)도 찾지 못합니다. `--password=…`처럼 영어 이름과 `=`로 적은 값은 찾습니다.
- 반대로 숫자가 섞인 소문자 설정값(`AUTH_MODE=oauth2-pkce`)은 비밀번호로 보고 가립니다. 이런 값도 Edit, Bash 같은 도구에서는 실제 값으로 바뀌므로 작업에는 지장이 없습니다.
- 가린 값이 코드의 다른 곳에 단독 단어로 나오면 그곳도 가립니다. `DB_PASSWORD=password1`을 가린 뒤에는 변수 이름 `password1`도 자리표시자로 보입니다.
- 모델의 실수로 값이 새는 일을 막는 장치입니다. 작정한 모델을 막는 격리 장치는 아닙니다. Bash로 값을 뒤집거나 잘라서 출력하면, 그 변형된 모양은 가려지지 않습니다.
- 대화 기록 파일의 구조화된 도구 기록(`toolUseResult`, 예를 들어 Edit의 diff나 Bash 표준 출력)에는 원본이 남을 수 있습니다. 모델은 이 기록을 읽지 않습니다.
- Read로 읽은 PEM 키는 줄 번호 접두어가 붙은 채로 등록됩니다. 그래서 그 자리표시자를 다른 파일에 쓰면 키가 깨집니다. 개인 키 파일을 옮길 때는 `cp`나 `cat a >> b`처럼 Bash로 파일째 옮기라고 요청하세요.
- 다른 플러그인이 시스템 프롬프트 조립(`prompt.compose`)을 먼저 가져가면 시스템 프롬프트 안내가 빠집니다. 값을 가린 행마다 붙는 한 줄 안내가 그 역할을 대신합니다.
- 자동 모드에서 Bash 호출이 권한 분류기에 넘어가면, 분류기는 실제 값으로 바뀐 명령을 읽습니다. 분류기도 모델입니다. 권한 판단은 치환이 끝난 입력으로 이루어지고, 플러그인이 그 입력을 바꿀 수 없기 때문입니다. 이 점이 걱정되면 그런 작업은 기본 권한 모드에서 맡기세요.
- 화면에 그려진 실제 값은 원격 화면(모바일, Remote Control)으로도 전달됩니다.
- ⧉ 복사는 답변 속 칩에서만 됩니다. 도구 행과 사용자 메시지에는 버튼을 넣을 수 없습니다. 모바일과 Remote Control에서는 아직 복사할 수 없습니다. 클립보드 도구도 없고 OSC 52도 지원하지 않는 터미널에서는 복사했다는 알림이 떠도 실제로는 복사되지 않았을 수 있습니다.

## 관리 설정이 있는 기계

관리 설정(`managed-settings.json`)이 있는 기계와 Team, Enterprise 조직에서는 내장 플러그인 `cc-plugin-sec-default`가 가장 바깥에 자리 잡습니다. 이 플러그인은 첨부와 시스템 프롬프트 내용을 사용자가 설치한 플러그인이 건드리지 못하게 넘겨 버립니다. 그래서 다음 내용은 이 플러그인이 가리지 못한 채 모델에게 갑니다.

- `@`로 언급한 파일, CLAUDE.md
- 압축 뒤 엔진이 다시 읽어 붙이는 파일, 읽은 뒤 바뀐 파일의 diff 알림

한 번 가렸던 값이라도 이 경로로 들어오면 원본 그대로 모델에게 갑니다.

조직 관리자가 이 플러그인을 관리 설정에 등록하면 이 문제가 없어집니다. `cc-plugin-sec-default`가 넘긴 이벤트는 `appendPlugins` 계층에서 다시 실행되기 때문입니다.

```json
{
  "enabledPlugins": { "secret-guard@whitekr-claude-plugins": true },
  "appendPlugins": ["secret-guard@whitekr-claude-plugins"]
}
```
